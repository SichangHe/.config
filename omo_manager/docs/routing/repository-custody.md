# repository custody

purpose

- transfer authority over exact untracked regular-file bytes without changing those bytes
- bootstrap later lifecycle work without treating closure receipts as ownership transfers

prepare

- authenticate the Human transfer authority and the source byte inventory through its durable report commitment
- bind each accepted source report's exact producer task and target
- require receiver acceptance to name the exact ordered paths and hashes
- prove the invoking process descends from the receiver's bound tmux pane
- bind both task files, their exact TODO membership rows, and live tmux process generations
- inspect tmux through a descriptor-pinned root-owned executable and a minimal environment
- bind repository device, branch, HEAD, upstream commit/ref/remote/URL, ahead/behind relation, full index, and full porcelain state
- run repository inspection through the pinned root-owned Git executable by descriptor, with a minimal environment and executable Git configuration disabled
- bind each unique relative path by no-follow file identity and SHA-256
- bind and retain every no-follow repository-to-leaf directory identity
- require every path and digest to occur in at least one authenticated source attestation
- publish one new owner-private canonical binding outside the repository

execute

- require an owner-private canonical PASS review for the exact binding
- rederive the complete binding before the prepared journal, ledger, and commit receipt
- rederive it again at the final publication boundary and before commit proof
- retain descriptors for every bound file through publication and revalidate afterward
- retain source-inventory/review report commitments as well as their envelopes
- claim one canonical source-keyed set of owner-private records with no-replace publication
- reject a colliding foreign directory, including an empty partial claim
- reject a second destination for the same source generation
- authenticate PASS through a durable report from a distinct task and target
- publish only append-only owner-private transaction records outside the repository
- resume a matching prepared or ledger-published transaction idempotently
- report conflicting or incomplete foreign state as indeterminate

non-effects

- never edit, copy, rename, stage, commit, or delete source bytes
- never change Git index or refs
- never change tasks, TODO, queues, panes, processes, mailbox, or Human contact
- the ledger changes custody evidence only; later lifecycle helpers need separate authority
