# agent status helper

`omo_agent_status.py` uses `TODO.md` as the linked task-file index, reads each linked task file's frontmatter for authoritative status, then summarizes active tasks with tmux status helper results.

It reports `missing`, `not_codex`, `running`, `error`, `ready`, or `stuck_input`; `missing` means the routed tmux target does not exist, while `not_codex` means the target exists but is not showing supported Codex or live Cursor Agent state. Completed registry rows are stale bookkeeping and can be pruned with `--prune-completed`. By default it exits `0` after a successful summary. With `--exit-code-if-active`, it exits `3` when any task is still active, meaning linked from `TODO.md` and not marked `done` or `blocked` in its task file.

With `--problems-only`, it stays silent unless a task file with frontmatter `status: running` is `error`, `missing`, `not_codex`, `ready`, or `stuck_input`, a `long_running` task is `error`, `missing`, `not_codex`, or `stuck_input`, a live TODO-section task file has nonempty `pending_task_items` after it is done, a blocked task is `error`, `missing`, `not_codex`, or `stuck_input`, a registry row or deduplicated `TODO.md`/task-file `runat` target that is no longer an inspected active row is visibly `error`, `missing`, `not_codex`, or `stuck_input`, an agent-owned tmux pane is not tracked by any task file, the optional `--manager-target` pane is `error`, `missing`, `not_codex`, or `stuck_input`, or a completed registry row is stale. A blocked task with a recorded human wait, including exact `blocked_on: human`, suppresses only a healthy `ready` pane; `error`, `missing`, `not_codex`, and `stuck_input` remain problems. A blocked manager also suppresses a healthy `ready` pane for an owned dependency tree: every blocker list is an exact comma-separated list of distinct task files; blocked intermediate nodes are managers with the same rule; and every distinct leaf has valid active frontmatter with no `(pending)` report. Missing, done, malformed, duplicate, cyclic, self, ambiguously owned, target-reusing, or report-bearing nodes and dependency text mixed with prose alert; launch failures on active leaves remain separate problems. `--manager-target` only adds a manager self-check; it does not filter worker tasks.

When any such problem exists, it prints only those rows, includes only nonzero problem-class counts, and exits `3`. Rows carry `owner_target=` when a task's manager is known. VL rows that lack `managerat:` are attributed to the active `vl_submanager_current_*` or `vl_supervisor_current_*` target when one is linked, so the pending watcher can dispatch each row to the responsible manager.

TODO-linked active records rejected by strict metadata parsing are reported as `malformed_task` with the parser error preserved for manager repair. A scan containing one is visibility-only: it may inspect and report state, but it cannot send input, auto-unstick, interrupt, stop, or replace any pane.

Blocked persistent-manager labels without a recorded human wait or concrete dependency tree alert like other blocked tasks. Explicit dependencies use the recursive exact-list rule for a blocked manager root and each blocked manager below it; workers do not become quiet merely by naming a running dependency. A deliberately closed blocked or long-running manager is also quiet when its body records manager closure of that exact target, its `blocked_on` names only live current task-file dependencies, and the capture contains no visible output, even when the closed manager remains in `TODO.md`'s `previous` section. An exact `paused by direct human shutdown instruction` blocker also makes a closed non-human target quiet when it repeats the exact target, says the task record or pending queue is preserved for explicit resume, and the body records that target's closure. The exact `vl_rebuild_mgr.md` record under `previous` is also quiet for its exact source-bound `human token-quota pause` blocker. Both intentional-pause rules require a missing target; a target that resolves, has visible non-Codex text, a pending marker, an `error`, or `stuck_input` remains a problem. Fallback rows are marked `role=registry_unmanaged`, `role=todo_unmanaged`, or `role=tmux_unmanaged` and keep the task-file status when available; missing historical tmux targets with no visible pane output are ignored. Tmux sessions starting with `h` are human-owned and ignored by agent tracking; other running, ready, errored, or stuck Codex panes without a task-file owner are `untracked_agent`.

Before registry fallback scans, indexed non-`done` task files without an unresolved `(pending)` delivery marker reserve their authoritative `runat` targets, including quiet human waits. Pending-delivery targets remain eligible for non-completed registry recovery rows; completed registry rows at claimed targets remain bookkeeping-only. All non-`done` targets are reserved before historical TODO fallback so completed entries cannot claim output from a reused pane.

Non-blocked `stuck_input` panes are submitted with Enter when `omo_codex_status.py` says the visible input is safe. Blocked task files are not auto-submitted.

Do not remove or mask TODO target suffixes to hide stale panes; if TODO target suffixes are cleaned, the helper uses task-file `runat` targets and scoped live `vl` error/stuck-input scanning instead of broad shell/editor `not_codex` scanning.

Persistent-role standby is durable task-file frontmatter: set `status: blocked` and put the persistent-role reason in `blocked_on`. Current persistent VL roles are `vl_supervisor_5410.md`, `vl_proof_analysis_5410.md`, `vl_spec_analysis_5410.md`, `vl_proof_runner_5410.md`, and `vl_spec_runner_5410.md`.

`status: long_running` is for managers and persistent human-facing interactive agents and may include `blocked_on` for a persistent role reason. A healthy ready pane is quiet because readiness is not a closure request. With `blocked_on`, pending-item reminders are suppressed; without it, they remain active. `error`, `not_codex`, `stuck_input`, malformed metadata, and launch failures remain problems.
