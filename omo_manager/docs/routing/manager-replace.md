# Atomic manager replacement

`omo_manager_replace.py` closes one exact live failed manager, migrates every active child to one new target, and publishes one blocked plain-Codex successor. It never starts the successor or resumes an old PCODX session. A later normal `omo_task.py` launch with manager instructions is deliberately separate, after this helper has proved that the successor is the sole active owner and that its target is absent.

The invocation binds:

- old manager, TODO, and every active child by SHA-256;
- the complete active-child set and each child's unchanged pending queue;
- old and new manager targets, parent manager, Codex session UUID, pane id, pane PID, and process start ticks;
- an owner-private Human source excerpt plus the digest of the one existing `<human_instruction authoritative="true">` block in its task envelope;
- an owner-private audit path, distinct preparer/reviewer identities, and any explicitly protected targets.

The selected authenticated Human lines must explicitly establish manager failure, non-execution, and replacement. A merely `running` record or arbitrary manager-mail text is insufficient. One narrow direct-close exception is supported: an exact whole line of `Replace the failed PCODX manager TASK at TARGET with one fresh plain-Codex manager inheriting all tasks and comments.` followed by the sole other nonblank selected/body line `Just do it` establishes failure, replacement, closure, and inheritance without a separate non-execution statement or `Close TARGET` directive. It must bind the exact old task and target; prefixes, suffixes, extra content, contradictions, and ambiguity fail closed. The successor stores only a digest-bound private source locator in its queue; it does not duplicate the private Human excerpt into ordinary task or TODO artifacts.

Source and envelope bodies use the same `splitlines()` plus newline-join normalization for their exact-content comparison. This removes only line-ending representation and trailing empty selected lines; source bytes, selected range, envelope block, and their digests remain independently exact-bound.

Source-1269 has one non-reusable exception for `guest_hees_mail_mgr.md` at `guest_hees:0`: only the exact authenticated `manager_mail/85c5dff58359-1269.txt:3-9` text is accepted. The whole ordered old-manager queue must also be bound with `--old-queue-sha256`. Any changed wording, range, source, task, target, queue, quotation, or later revocation fails closed. If the original bound stop lost its guard after closing the exact pane and unrelated lifecycle work later changed TODO or Markdown membership, a fresh audit may cite the immutable failed audit with `--closed-owner-audit` and `--closed-owner-audit-sha256`. The source audit remains unchanged. The fresh transaction requires its original task and children unchanged, the old symbolic target, pane id, PID, and successor target absent, no bound close proof, and the original prepared audit plus close authority reconstructed exactly; it then binds the current TODO and complete Markdown membership before writing.

The helper takes the root-membership lock, both target locks, every current Markdown task lock, and locks for its audit/proof paths. It rejects stale membership or bytes, malformed ownership, duplicate owners, omitted or extra children, and any live or owned successor target. Ordinarily, old/new targets in `h*` or the protected set remain forbidden.

The sole protected-`h*` exception is the exact four-child Human-authorized PCODX replacement mode. It requires all six additional SHA-256 bindings: the old manager's full ordered queue, canonical live PCODX environment state, ledger bytes, installed wrapper bytes, ordered protected-pane/process inventory, and the complete authority-envelope file. The authenticated selected Human lines must name the exact old task and protected target and explicitly identify PCODX, failure, non-execution, and replacement, except that the exact sentence above supplies the non-execution and direct-close evidence through its narrow semantics. The old task must be `tool: pcodx`; its protected `h*` target must be in the bound protected set; the successor target must be non-Human and unprotected. Every binding is rechecked under the transaction locks before the first pane input. Missing authority, an incomplete child set, task/TODO/queue drift, a changed Codex session, PCODX state or custody, pane/process identity, ledger, wrapper, envelope, protected inventory, or concurrent mutation fails closed.

The old pane is stopped only through the guarded exact-pane close capability; every read and mutation is server-guarded by symbolic target, pane id, and pane PID, while process start ticks are rechecked around the interaction. Protected-`h*` closure also reuses the independently authenticated direct Human close authority and queues the durable close proof after the exact pane kill. A durable close proof is written before lifecycle bytes change. The helper never constructs or runs a PCODX resume command.

Global tmux inventory excludes only panes that tmux itself marks dead. Every row marked live must still resolve to a current process start tick, or replacement fails closed before any pane interaction.

Write order is old-manager closure, all child migrations, TODO migration, then successor publication. Existing files are replaced with Linux inode exchange, and successor publication uses atomic no-replace linking; a concurrent path rebind is preserved instead of overwritten or unlinked. The successor stays `blocked` with its inherited ordered queue, `tool: codex`, and no inherited session ID or PCODX custody. Final proof requires unchanged Markdown membership apart from the successor, no active old-target owner or child, exactly the successor at the new target, the exact migrated child set, unchanged child queues, unchanged successor queue, unchanged non-replaced protected panes, and both old/successor panes absent.

The private audit embeds all before/after images and the exact close capability, and advances through `prepared`, `owner_stopped` or `owner_absent`, `mutating`, `proving`, then `committed`. An interruption can be retried with the identical invocation and audit path: the helper authenticates the audit, reconstructs canonical bytes from the bound Human source, proves the close, commits an already-complete state, or rolls a partial state back before continuing. A bound child process revalidates the symbolic target, numeric pane, PID, and process start time, kills the numeric pane, proves pane/process absence, then writes the capability proof; loss of the parent guard marker is accepted only when that proof exists. Source-1269 alone can reconcile its already-recorded proofless guard-loss incident as `owner_absent`: it does not claim a successful guarded close, and requires the exact guest target, numeric pane, and bound process all absent, every lifecycle file at its exact before-image, and the original prepared audit and Human-bound close authority reconstructed byte-for-byte. This manager-only reconciliation is not accepted by ordinary task parking. Unknown bytes and incomplete rollback fail closed with durable evidence. Ordinary failures reverse transaction-owned writes in reverse order and record `rolled_back`; any incomplete reversal records `rollback_failed`. Concurrent unsupported edits to a not-yet-written task or TODO are preserved and cause fail-closed rollback.

Use `--child TASK.md=SHA256` once for every active child, in any order. Bind authority with `--authority-file`, `--authority-lines`, `--authority-sha256`, `--authority-envelope-task`, and the selected block's `--authority-envelope-sha256`; select the replacement directive with one or more contained `--successor-item-lines`. On the first run, `--audit-output` must name a nonexistent file in an owner-private directory. The same path is the recovery key after an interruption. The helper prints a success message only after the singular ownership proof; it does not print or run a launch command.

For the exact Source-1289 whole-tree replacement, add exactly one `--descendant TASK.md=SHA256=TARGET=PANE_ID=PANE_PID=START_TICKS=SESSION_UUID=QUEUE_SHA256` for every `--child`. The authenticated invocation must bind the complete Source-1289 file and select its exact lines 3–10 tree directive. The child and descendant task/digest sets must match exactly, and nested active descendants are rejected rather than omitted. This mode binds each live descendant task, complete task bytes, ordered queue, target, pane, process, start time, and Codex session. It guarded-closes every descendant before the old manager, records a separate binding-bound progress record, close capability, and durable proof for each, and rejects a changed, omitted, extra, human-owned, protected, parent, or aliased target. Recovery reuses already-proved closes and never targets them again. If a pane disappears before its proof is durable, the progress record preserves that ambiguity and fails closed for explicit reconciliation instead of retrying. The final proof requires every bound descendant pane and process absent, every close proof present, progress clear, all child records migrated with unchanged queues, the old manager done, and exactly one blocked unlaunched successor.

When the complete locked tree has no active child, the exact Source-1289 program may instead use `--empty-tree-envelope-sha256 SHA256`. This narrow mode also authenticates the owner-private Source-1292 file at its fixed digest and the exact Source-1292 lines 1–4 envelope block containing `Close either way. Directly use tmux if needed`. It rejects any child or descendant pin, any active child discovered from task frontmatter, missing or changed dual authority, and every ordinary target/identity/protected-pane drift. The guarded old-manager close, complete before-image audit, rollback, recovery, queue inheritance, blocked plain-Codex successor, and final sole-owner proof remain unchanged. Historical done child records and their evidence are neither edited nor included in the replacement write set.

For the protected-`h*` PCODX exception, also pass `--old-queue-sha256`, `--old-pcodx-state-sha256`, `--old-pcodx-ledger-sha256`, `--old-pcodx-wrapper-sha256`, `--protected-targets-sha256`, and `--authority-envelope-file-sha256`. `--protected-target` order is part of the inventory digest. The mode is unavailable unless all six bindings are present and exact.
