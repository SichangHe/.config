# task launch helper

`omo_task.py --task-file TASK.md --tmux-session SESSION --workdir DIR --model MODEL --reasoning-effort EFFORT --prompt-file PROMPT` creates and links task files, opens a tmux window with its normal shell, then starts Codex with the selected model and reasoning effort through `bunx @openai/codex --dangerously-bypass-approvals-and-sandbox`. `--tmux-session` is required for launch and registration; manager-ownership migration is the only mode that omits it.

`--workdir`, nonempty `--model`, and `--reasoning-effort` are mandatory when launching a new worker. If the exact named session exists, its tmux `session_path` and `--workdir` must refer to the same filesystem directory; equivalent symlink paths match. A mismatch or an unverifiable path fails before tmux, task, or TODO mutation. A matching existing session keeps the normal `new-window` path and is bound by its tmux session ID, so replacement of that name before mutation fails instead of targeting the replacement. A missing session is created with `new-session` at `--workdir`, and its first window becomes the worker window. If tmux returns blank identity and path fields with a successful status, an exact `has-session` check must confirm absence before creation; a blank response for an existing session remains an error. Because tmux chooses a new session's first window index, a missing session combined with `--tmux-window` is rejected before mutation; dry-run uses the synthetic `SESSION:DRYRUN` target where that automatic index is not yet knowable.

Without `--workdir`, `omo_task.py` only registers the task against an exact existing ready or running Codex pane named by `--tmux-session` and `--tmux-window`; it does not create a session or window or start Codex. Missing sessions and missing, shell-only, exited, or error panes are rejected with instructions to use `--workdir`.

`--task-file` is manager-side bookkeeping for `omo_task.py`; keep that path out of worker prompts. Workers report from their own tmux pane with `omo_report.sh --alloc-message-file` and `omo_report.sh --status STATUS --message-file FILE`, without `--task-file`, `--root`, `--manager-target`, or other manual route flags.

Use `--tool pcodx` only for a worker that intentionally needs the PCODX CLI wrapper, its scoped `pcodx_partial_compact` MCP tools, and sidecar ledger artifacts under `/tmp/pcodx-runs`; that path records `tool: pcodx` in task frontmatter.

New ordinary worker tasks start with `status: running`; `--is-manager` tasks start with `status: long_running` and `blocked_on: persistent manager role`. New frontmatter also contains `version`, `runat`, `tool`, `managerat`, `is_manager`, and `pending_task_items: []`. `--manager-target TARGET`, or the current `OMO_AGENT_TMUX_TARGET`, supplies `managerat`. After launch, each agent maintains still-open work through the path-opaque `omo_pending.py list|add|replace|remove` interface. Managers retain lifecycle, routing, launch, and closure ownership. Pending-message routing is documented separately in the watcher docs.

Non-submanager VL worker launches, identified by a `vl_` task filename or the `vl` tmux session, require `--manager-target` so reports and watcher status route to the owning VL submanager. Raw `--codex-flag` MCP server config tokens such as `mcp_servers.*` require explicit `--tool pcodx`, so ordinary new Codex agents do not inherit private partial-compaction MCP registration. The MCP tools provide an auditable partial-compaction ledger; they do not rewrite Codex's hidden native transcript.

Every prompted Codex and PCODX launch begins its initial prompt with `WORKER_DEFAULTS.md`, including launches without `--prompt-file`; `--resume-idle` is the no-prompt recovery exception. Prompted VL launches add `VL_WORKER_DEFAULTS.md` after the common defaults and still require `--prompt-file` for task-local context. Manager launches selected with `--is-manager` then add `ROOT/MANAGER.md`; the launch fails before task, TODO, or tmux mutation if that file is missing or unreadable. The launcher labels `--prompt-file` content as agent-authored with `<manager_delegation from="MANAGER_TARGET">`. The complete order is common worker defaults, optional VL defaults, optional manager instructions, manager delegation, then any authoritative human excerpt.

The PB-specific continuation and human-email rule in `WORKER_DEFAULTS.md` has the same deployment boundary: newly prompted launches receive it; already-running agents and `--resume-idle` launches do not.

Use paired `--human-email-file FILE --human-email-lines START-END` options with `--prompt-file` on `--workdir` launches to append an inclusive excerpt from human email as the final prompt content. The custom prompt supplies the agent-authored task goal and subgoals; the email options supply the separately labeled human words. Relative `FILE` paths resolve from `ROOT`, and the resolved path must remain inside `ROOT/manager_mail`. The launcher requires both options, validates that the readable file and `END` line exist before mutation, preserves the selected text exactly, and wraps it in `<human_instruction authoritative="true" source="FILE:START-END">` tags. It rejects excerpts containing `</human_instruction>`. The durable task body and worker prompt both retain the root-relative source and selected lines so later agents can distinguish exact human words from manager synthesis. The wrapped runtime excerpt uses an owner-private temporary file across any update retry and is removed after launch verification. These options are not accepted in registration-only, resume-idle, or manager-ownership-migration mode.

Tmux sessions whose names begin with `h` are human-owned. `omo_task.py --workdir` validates the exact requested session and rejects launches into that namespace before creating a session or window or writing task state unless the authoritative `--human-email-file` excerpt contains an unquoted, non-negated explicit launch request naming that exact session on the same line. Accepted wording includes `launch`, `create`, `start`, `open`, or `spawn`, plus requests such as `give me an agent`, `set up an agent`, or `I want/need/would like an agent`. Mentions, quoted requests, and lines containing negation or prohibition do not authorize mutation. Managers must otherwise choose a non-`h` session.
Manager rotation always rejects `h*` targets. Lower-level `omo_codex_start.py` also rejects them except for its documented byte-exact, same-pane `hwl:3` restart authorization; that exception cannot launch, create, move, or recover any other human-owned pane.

Launcher-managed defaults and `MANAGER.md` are prompt-only. The task body stores each `--prompt-file` inside a manager-delegation envelope and stores each selected human excerpt in a separate authoritative human-instruction envelope. The launcher rejects a manager prompt containing `<human_instruction` or `</manager_delegation>` and rejects a human excerpt containing `</human_instruction>`, so neither source can forge the other's provenance boundary. The initial prompt is passed as Codex's launch argument, not pasted after a startup sleep or injected into an existing Codex TUI input line.

Use `--prelaunch-source SCRIPT` when a worker needs launcher-time environment setup. `omo_task.py` sources that readable shell script inside the worker pane before exporting `OMO_AGENT_TMUX_TARGET` and starting Codex.

Transfer an existing task to a different manager with `omo_task.py --root ROOT --task-file TASK.md --migrate-manager-owner --old-manager-target OLD --new-manager-target NEW`. This operation requires valid frontmatter whose single `managerat` exactly matches `OLD`, atomically changes only that value, and performs no pane, prompt, status, TODO, or launch action. Add `--dry-run` to validate and preview the change without mutating any file or pane.

The helper writes task/TODO state after tmux creates the worker target and before starting Codex, then verifies that the pane leaves the shell. A Codex launch failure is explicit but can leave that manager-owned bookkeeping in place for diagnosis or retry. When tmux cannot create the session or window, the error names a private temporary diagnostic file containing the exact failed tmux command, selected tmux environment, task/prompt/workdir state, exit status, stdout, stderr, and any current session windows. For a directory-trust prompt, `omo_task.py` records the newly created pane's exact tmux ID and pre-launch capture, emits a full UUID marker absent from that baseline, and recognizes only Codex's contiguous bottom-anchored `You are in`/warning/choices/confirmation frame. Confirmation also requires exactly one live `bunx @openai/codex` launch below the pinned pane process; `h*` sessions are never auto-confirmed. Immediately before selecting the default `Yes, continue` choice once, the helper rechecks that process provenance and requires the logical task target to resolve to the same pane ID, then sends Enter to that exact ID. Split-window active-pane changes, stale scrollback, unframed text, registration-only panes, and arbitrary `not_codex` panes cannot authorize confirmation. If Codex stops on its update prompt, the helper presses Enter to run the update, waits for the restart message, and reruns the original launch command once.

Use `--model MODEL_NAME` for model selection and follow `MANAGER.md` for the current model policy. `--reasoning-effort EFFORT` passes `--config 'model_reasoning_effort="EFFORT"'`; allowed values are `low`, `medium`, `high`, `xhigh`, `max`, and `ultra`. Both model and reasoning effort are emitted explicitly for fresh and prompted resumed Codex and PCODX launches. Use repeatable `--codex-flag` only for unrelated extra Codex argv tokens, for example `--codex-flag=--profile --codex-flag deep-review`; raw `--model...` and `-m...` tokens are rejected. Use `--session-id UUID` to start `codex ... resume UUID` or, with `--tool pcodx`, `pcodx ... resume UUID` instead of a fresh session. Pane 0 is implied.

For recovery that must preserve the resumed TUI's idle input and authorization state, add `--resume-idle`. It requires `--session-id` and launch mode with `--workdir`, submits no prompt, and therefore does not require model or reasoning overrides. Codex resumes receive that exact work directory through `--cd`, preventing its interactive current-versus-session directory chooser; PCODX resumes retain their existing CLI contract. In an existing session, `--tmux-window INDEX` pins the new window to that exact free index and tmux rejects an occupied index. Use isolated or existing correct bookkeeping when recovery must not change the original task or pending queue.
