# Agent audit helper

`omo_agent_audit.py` is a disabled-by-default audit view for Codex JSONL. Enable it explicitly with `--enable` or through the watcher setting `OMO_MANAGER_ENABLE_AGENT_AUDIT=true`. It reads only a bounded byte tail, accepts the known `response_item` and `event_msg` envelopes, and binds records to the task's exact session UUID. Human-visible messages and bounded function-call metadata go into a private concise evidence file. Raw reasoning and system/developer content are excluded. Tool output is materialized only when the cheap reviewer asks for specific call IDs, in separate owner-only files.

Sampling chooses at most one eligible agent per pass and persists per-task timestamps in a private state file, enforcing the default 24-hour cooldown across watcher restarts. The watcher runs a pass every two hours by default. Temporary audit directories are owner-private and deleted after each pass; stale abandoned directories are also removed. A low-effort Luna reviewer handles the first pass. Problems, inconclusive results, and requests for selected tool evidence go to a high-effort Terra reviewer. Only Terra-confirmed problems are delivered: non-human managers receive an explicitly agent-originated message through an exact-process-guarded tmux send, while a worker owned directly by an `h*` target triggers human email without changing that pane.

New Codex launches record their UUID in task frontmatter using an identity-guarded `/status` query before the task prompt is submitted. `omo_codex_session_migrate.py --root ROOT` previews existing live non-human tasks that can be captured safely; add `--apply` to bind their UUIDs. Use `--task TASK.md --task-sha256 SHA256` to inspect and bind exactly one byte-pinned eligible root-relative task without inspecting other candidate panes; absence, ineligibility, or digest drift refuses the operation. Apply accepts ready or running panes and submits visible non-placeholder input once through the exact process guard before `/status`. Human-owned `h*` sessions are excluded by default and require the explicitly authorized `--include-human-owned` option. Retired tasks and ambiguous task ownership remain excluded.
